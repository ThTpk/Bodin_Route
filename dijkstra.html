Shortest Path Algorithm

Dijkstra's Algorithm — หาทางที่ "สั้นที่สุดจริง ๆ" โดยไม่ต้องลองทุกเส้นทาง

ถ้าจะเดินจากประตูโรงเรียนไปห้องสมุด เส้นทางที่เป็นไปได้มีมากมายจนนับไม่ไหว Dijkstra เป็นวิธีที่ทำให้คอมพิวเตอร์หา "ทางที่สั้นที่สุด" เจอ โดยไม่ต้องไล่ลองทุกเส้นทาง และรับประกันได้ว่าคำตอบสั้นที่สุดจริง หน้านี้จะพาไปดูตั้งแต่แนวคิด โค้ดจำลอง (pseudo code) ไปจนถึงภาพเคลื่อนไหวที่กดเดินทีละขั้นได้

1. โจทย์คืออะไร

เริ่มจากการเปลี่ยนแผนที่ให้เป็นสิ่งที่คอมพิวเตอร์เข้าใจ เรียกว่า กราฟ (graph) ซึ่งมีแค่สองอย่าง

  • โหนด (node) — จุดสำคัญ เช่น ห้องเรียน บันได ทางแยก ประตูโรงเรียน
  • เส้นเชื่อม (edge) — ทางเดินที่ต่อระหว่างสองโหนด พร้อม น้ำหนัก (weight) คือ "ราคา" ของการเดินเส้นนั้น เช่น ระยะทางเป็นเมตร หรือเวลาเป็นวินาที
โจทย์ single-source shortest path

เมื่อกำหนดกราฟ จุดเริ่มต้น และจุดหมาย จงหาลำดับของเส้นเชื่อมที่พาจากจุดเริ่มต้นไปถึงจุดหมาย โดยที่ ผลรวมของน้ำหนักน้อยที่สุด

ทำไมไม่ลองทุกเส้นทางไปเลย

เพราะจำนวนเส้นทางเพิ่มแบบระเบิด กราฟตัวอย่างในหน้านี้มีแค่ 11 โหนด 16 เส้นเชื่อม ก็มีเส้นทางให้ลองหลายสิบเส้นแล้ว ส่วนกราฟจริงของเว็บแผนที่นี้มีโหนดหลักร้อย ถ้าไล่ลองทุกความเป็นไปได้จะช้าจนใช้งานไม่ได้ Dijkstra จึงใช้วิธีที่ฉลาดกว่านั้น

2. แนวคิดหลัก — "คลื่นน้ำที่แผ่ออกจากจุดเริ่มต้น"

ภาพที่ตรงที่สุดคือ หยดน้ำลงบนจุดเริ่มต้น แล้วปล่อยให้คลื่นแผ่ออกไปด้วยความเร็วเท่ากันทุกทิศ คลื่นจะไปถึงที่ใกล้ก่อนเสมอ ดังนั้น "ลำดับที่คลื่นไปถึง" ก็คือ "ลำดับระยะทางจากใกล้ไปไกล" นั่นเอง Dijkstra คือการจำลองคลื่นนี้ด้วยตัวเลข

① ทุกโหนดมีตัวเลขประจำตัว dist

dist[v] = ระยะที่ดีที่สุดเท่าที่รู้ตอนนี้จากจุดเริ่มต้นถึง v
ตอนเริ่ม ทุกโหนดเป็น ∞ (ยังไปไม่ถึง) ยกเว้นจุดเริ่มต้นที่เป็น 0

② Relaxation — "ลองเส้นทางใหม่แล้วดีขึ้นไหม"

ยืนที่ u แล้วมองไปยังเพื่อนบ้าน v ถ้า dist[u] + น้ำหนัก(u,v) < dist[v] แปลว่าเจอทางที่ดีกว่าเดิม ก็อัปเดตตัวเลขและจำไว้ว่า "มาจาก u"

③ Greedy — เลือกโหนดที่ใกล้ที่สุดก่อนเสมอ

ทุกรอบให้หยิบโหนดที่มี dist น้อยที่สุดในบรรดาที่ยังไม่ได้ปิด ออกมาทำงาน — นี่คือหัวใจที่ทำให้อัลกอริทึมถูกต้อง

④ ปิดแล้วปิดเลย (settled)

โหนดที่ถูกหยิบออกมาแล้ว ถือว่า dist ของมันเป็นค่าที่สั้นที่สุดจริง ไม่ต้องกลับมาแก้อีก จึงไม่มีการวนซ้ำไปมา

คิวลำดับความสำคัญ (priority queue) คืออะไร

คือกล่องเก็บโหนดที่ "รู้จักแล้วแต่ยังไม่ปิด" ซึ่งหยิบตัวที่ค่าน้อยที่สุดออกมาได้เร็ว ถ้าใช้การไล่หาทีละตัวจะช้า จึงนิยมใช้โครงสร้างชื่อ binary heap ที่หยิบตัวน้อยสุดได้ในเวลา O(log n) (ในโปรเจกต์นี้เขียนไว้ที่คลาส MinHeap ใน js/graph.js)

3. Pseudo code และภาพจำลองที่กดเดินได้

กด เล่นอัตโนมัติ หรือ ถัดไป เพื่อเดินทีละขั้น ระหว่างเล่นให้สังเกตสามอย่างพร้อมกัน คือ บรรทัด pseudo code ที่ถูกไฮไลต์ ตัวเลขในตาราง และสีของโหนดในภาพ (คลิกที่โหนดใดก็ได้เพื่อเปลี่ยนจุดหมายแล้วดูใหม่)

  1. ฟังก์ชัน Dijkstra(กราฟ G, จุดเริ่ม s, เป้าหมาย t):
  2. สำหรับทุกโหนด v ใน G:
  3. dist[v] ← ∞ , prev[v] ← ว่าง
  4. dist[s] ← 0
  5. Q ← คิวลำดับความสำคัญ, ใส่ s ด้วยค่า dist[s]
  6. ขณะที่ Q ยังไม่ว่าง:
  7. u ← โหนดใน Q ที่ dist น้อยที่สุด (ดึงออกมา)
  8. ถ้า u = t : ออกจากลูป
  9. ทำเครื่องหมายว่า u ปิดแล้ว (settled)
  10. สำหรับทุกเพื่อนบ้าน v ของ u:
  11. ถ้า v ปิดแล้ว : ข้ามไปตัวถัดไป
  12. alt ← dist[u] + w(u, v) // ระยะถ้าเดินผ่าน u

  14. dist[v] ← alt

4. เดินทีละขั้นด้วยมือ

ตารางนี้คือการทำงานทั้งหมดของภาพด้านบน จาก S (ประตูโรงเรียน) ไป H (ห้องสมุด) หนึ่งแถวคือหนึ่งรอบของลูป while คือ "ดึงโหนดที่ใกล้ที่สุดออกมาหนึ่งตัว แล้วอัปเดตเพื่อนบ้าน"

รอบ ดึงออกจากคิว ระยะที่ยืนยัน อัปเดตเพื่อนบ้าน (relaxation) คิวหลังจบรอบ

2P ลานจอดรถ130 Q ผ่าน P ได้ 285 ซึ่งแย่กว่า 130 → ไม่เปลี่ยน Q:130, A:140, B:140, D:300
3Q โรงอาหาร130 เพื่อนบ้านปิดหมดแล้ว → ไม่เปลี่ยน A:140, B:140, D:300
4A อาคาร 1140 C: ∞→265 · D ผ่าน A ได้ 305 แย่กว่า 300 → ไม่เปลี่ยน B:140, C:265, D:300
5B สนามกีฬา140 E: ∞→265 · D ผ่าน B ได้ 300 เท่าเดิมพอดี → ไม่เปลี่ยน C:265, E:265, D:300
6C อาคาร 2265 F: ∞→390 E:265, D:300, F:390
7E หอประชุม265 G: ∞→395 D:300, F:390, G:395
8D ลานกลาง300 F ผ่าน D ได้ 450 · G ได้ 450 แย่กว่าเดิมทั้งคู่ → ไม่เปลี่ยน F:390, G:395
9F อาคาร 3390 H: ∞→525 G:395, H:525
10G โรงยิม395 H ผ่าน G ได้ 535 แย่กว่า 525 → ไม่เปลี่ยน H:525
11H ห้องสมุด = เป้าหมาย525 เป้าหมายถูกดึงออกจากคิว → หยุดทันที ว่าง

ย้อนรอยหาเส้นทาง

อัลกอริทึมไม่ได้เก็บ "เส้นทาง" ไว้ตรง ๆ แต่เก็บแค่ prev ว่าแต่ละโหนดเดินมาจากใคร พอถึงปลายทางก็เดินย้อนกลับ

H ← F ← C ← A ← S   ⇒   กลับด้านได้เส้นทาง S → A → C → F → H รวม 525 เมตร
จุดที่คนมักเข้าใจผิด

ในรอบที่ 8 โหนด D ถูกดึงออกด้วยระยะ 300 ซึ่งสั้นกว่า F (390) แต่สุดท้าย D กลับไม่ได้อยู่ในคำตอบ เพราะ "อยู่ใกล้จุดเริ่มต้น" ไม่ได้แปลว่า "อยู่บนเส้นทางที่ดีที่สุดไปยังปลายทาง" Dijkstra ไม่รู้ว่าปลายทางอยู่ทางไหน มันจึงต้องแผ่คลื่นออกไปทุกทิศ — ข้อนี้เองที่ A* Search เข้ามาแก้

5. ทำไมถึงได้คำตอบที่สั้นที่สุดเสมอ

คำถามสำคัญคือ ตอนที่เราหยิบโหนด u ที่มีค่า dist น้อยที่สุดออกจากคิว ทำไมจึงมั่นใจได้ว่าไม่มีทางอื่นที่สั้นกว่านี้อีกแล้ว ทั้งที่ยังไม่ได้สำรวจกราฟทั้งหมด

เหตุผลแบบไม่ใช้สัญลักษณ์คณิตศาสตร์

สมมติว่ามีทางลับที่ไปถึง u ได้สั้นกว่าค่าที่เรามี ทางลับนั้นต้องเริ่มจากจุดเริ่มต้นแล้ว "ออก" จากกลุ่มโหนดที่ปิดไปแล้ว ผ่านโหนดสักตัวที่ยังอยู่ในคิว เรียกว่า x

แต่ x ก็อยู่ในคิวเหมือนกัน และเราเลือก u เพราะ u มีค่าน้อยที่สุด ดังนั้น dist[x] ≥ dist[u] เสมอ เมื่อทางลับต้องเดินผ่าน x ต่อไปอีก และทุกน้ำหนักไม่ติดลบ ระยะทางมีแต่จะเพิ่ม ทางลับจึงยาวกว่าหรือเท่ากับค่าที่เรามีอยู่แล้ว — ขัดแย้งกับที่สมมติไว้

สรุป: ทางลับที่สั้นกว่าไม่มีทางมีอยู่จริง ค่า dist[u] ที่หยิบออกมาจึงเป็นคำตอบสุดท้ายได้เลย

เงื่อนไขสำคัญ: ห้ามมีน้ำหนักติดลบ

เหตุผลข้างบนพังทันทีถ้ามีเส้นเชื่อมน้ำหนักติดลบ เพราะการเดินต่ออีกก้าวอาจทำให้ระยะลดลงได้ กรณีนั้นต้องใช้อัลกอริทึมอื่น เช่น Bellman–Ford โชคดีที่ระยะทางและเวลาเดินในโลกจริงไม่มีทางติดลบ Dijkstra จึงเหมาะกับงานแผนที่พอดี

6. ความเร็วและข้อจำกัด

หัวข้อรายละเอียด
เวลาทำงานO((V + E) log V) เมื่อใช้ binary heap (V = จำนวนโหนด, E = จำนวนเส้นเชื่อม)
หน่วยความจำO(V) สำหรับตาราง dist, prev และคิว
ต้องการน้ำหนักทุกเส้น ≥ 0
ได้ผลพลอยได้ระยะสั้นที่สุดจากจุดเริ่มต้นไปทุกโหนด ไม่ใช่แค่ปลายทางเดียว
จุดอ่อนไม่รู้ว่าปลายทางอยู่ทิศไหน จึงสำรวจโหนดที่ไม่เกี่ยวข้องไปเยอะ

ในกราฟตัวอย่างของหน้านี้ Dijkstra ต้องดึงโหนดออกจากคิวถึง 11 ครั้ง จากทั้งหมด 11 โหนด คือแทบสำรวจทั้งกราฟ ขณะที่ A* ซึ่งรู้ทิศทางคร่าว ๆ ของปลายทางใช้เพียง 7 ครั้ง (ลดลงราว 36%) โดยได้เส้นทางเดียวกันเป๊ะ

7โหนดที่ A* สำรวจ

7. ใช้ในโปรเจกต์นี้อย่างไร

โค้ดจริงอยู่ในไฟล์ js/graph.js ซึ่งใช้ Dijkstra สามที่

  • เมธอด shortestPath() — เป็นโค้ดชุดเดียวกับ A* เพียงแต่เมื่อเลือก algorithm: 'dijkstra' จะตั้งค่าประมาณ (heuristic) เป็นศูนย์ทั้งหมด ซึ่งทำให้กลายเป็น Dijkstra แท้ ๆ ทันที (ในหน้าแผนที่เลือกได้จากช่อง "อัลกอริทึม")
  • เมธอด nearest() (multi-target Dijkstra) — ใช้กับปุ่ม "หาโหนดที่ใกล้ที่สุด" เดินคลื่นออกจากจุดเริ่มต้นรอบเดียว แล้วเก็บบันได/ทางเชื่อม/ห้องเรียนที่คลื่นไปถึงตามลำดับ เร็วกว่าการหาเส้นทางทีละเป้าหมายมาก
  • คลาส MinHeap — คิวลำดับความสำคัญที่ทำให้การหยิบโหนดค่าน้อยสุดเร็วเป็น O(log n)

รายละเอียดของกราฟจริงในเว็บนี้

  • น้ำหนักเลือกได้สองแบบ คือ ระยะทาง (เมตร) หรือ เวลา (วินาที)
  • บันไดเป็นเส้นเชื่อมแบบมีทิศทาง เพราะขึ้นบันไดใช้เวลา 20 วินาที แต่ลงใช้ 15 วินาที
  • ตัวเลือก "เลี่ยงบันได" ทำงานโดยกรองเส้นเชื่อมชนิดบันไดออกตอน relax ไม่ได้สร้างกราฟใหม่
ลองเองได้

เปิดหน้าแผนที่ 3 มิติ เลือกจุดเริ่มต้นกับจุดหมาย แล้วสลับช่อง "อัลกอริทึม" ระหว่าง Dijkstra กับ A* ผลลัพธ์เส้นทางจะเหมือนกันเสมอ แต่ตัวเลข "จำนวนโหนดที่สำรวจ" ในผลลัพธ์จะต่างกันชัดเจน

อ่านต่อ A* Search → Dijkstra ที่เพิ่ม "เข็มทิศ" ให้รู้ว่าปลายทางอยู่ทิศไหน จึงเร็วกว่าโดยยังได้คำตอบสั้นที่สุดเท่าเดิม กลับไป แผนที่กราฟ 3 มิติ → ทดลองค้นหาเส้นทางบนกราฟจริงของอาคารเรียน พร้อมสลับอัลกอริทึมได้

ภาพจำลองในหน้านี้รันอัลกอริทึมจริงในเบราว์เซอร์ ไม่ได้เป็นภาพที่อัดไว้ล่วงหน้า โค้ดอยู่ที่ js/learn-viz.js ส่วนอัลกอริทึมที่ใช้งานจริงอยู่ที่ js/graph.js
