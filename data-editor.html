Data Format Workshop

เขียนไฟล์ข้อมูลเอง แล้วเห็นผังของตัวเองลอยขึ้นมาทันที

แผนผัง 3 มิติในเว็บนี้ไม่ได้วาดด้วยมือ แต่คำนวณขึ้นจากไฟล์ข้อความล้วน ๆ สามไฟล์ หน้านี้จะพาไปดูว่าแต่ละไฟล์เก็บอะไร ต้องเขียนอย่างไร แล้วเปิดช่องให้แก้ JSON ได้บนหน้าเว็บโดยตรง ทุกครั้งที่พิมพ์เสร็จ ระบบจะตรวจความถูกต้องและวาดโหนดกับเส้นเชื่อมใหม่ให้ทันที

ตัวอย่างเริ่มต้น 3 อาคาร × 3 ชั้น × 2 ห้อง ตรวจข้อมูลด้วยกติกาเดียวกับ validate_data.py วาดด้วย js/view3d.js ตัวเดียวกับหน้าจริง ดาวน์โหลดไฟล์ที่แก้แล้วได้

1. สามไฟล์ทำหน้าที่อะไร

ระบบมองโรงเรียนเป็น กราฟ (graph) ไม่ใช่รูปภาพ กราฟมีแค่สองอย่างคือ "จุด" กับ "เส้นที่ต่อระหว่างจุด" ไฟล์ข้อมูลจึงแบ่งตามนั้นพอดี แล้วเพิ่มไฟล์ที่สามไว้บอกว่าจุดพวกนั้นอยู่ในอาคารหลังไหน

① data/buildings.json — ทะเบียนอาคาร

บอกว่ามีอาคารอะไรบ้าง ชื่ออะไร สีอะไร สูงกี่ชั้น และค่ากลางของทั้งผัง เช่นความสูงต่อชั้น ไม่มีผลต่อการหาเส้นทาง แต่ทำให้ภาพและคำบอกทางอ่านรู้เรื่อง

② data/nodes.json — จุดทั้งหมด

หนึ่งบรรทัดคือหนึ่งจุดที่คนไปยืนได้ — ห้องเรียน บันได ทางเชื่อม แต่ละจุดมี id ที่ห้ามซ้ำ และมีพิกัด x, y กับหมายเลข floor ที่บอกว่าอยู่ชั้นไหน

③ data/edges.json — เส้นที่ต่อระหว่างจุด

บอกว่าเดินจากจุดไหนไปจุดไหนได้ พร้อม น้ำหนัก คือ distance (เมตร) และ time (วินาที) นี่คือไฟล์ที่ Dijkstra กับ A* ใช้จริง ๆ ในการหาเส้นทางสั้นที่สุด

ที่ไม่มีในไฟล์: แกนสูง

ไม่มีฟิลด์ z ที่ไหนเลย เพราะความสูงถูกคำนวณจาก floor ตอนวาดภาพ (z = (floor − ชั้นล่างสุด) × ระยะห่างระหว่างชั้น) จึงปรับระยะห่างบนภาพได้โดยไม่ต้องแตะข้อมูลเลย

กฎเหล็กข้อเดียวที่ต้องจำ

edges.json อ้างถึงโหนดด้วย id เท่านั้น ถ้าพิมพ์ id ผิดแม้ตัวเดียว เส้นนั้นจะหายไปทั้งเส้น และถ้าเพิ่มโหนดใหม่แต่ลืมเพิ่มเส้นเชื่อม โหนดนั้นจะกลายเป็นจุดลอยที่เดินไปไม่ถึง

2. ห้องทดลอง — แก้แล้วเห็นผลทันที

ช่องซ้ายคือไฟล์ทั้งสาม สลับดูได้ด้วยแท็บด้านบน แก้ได้ตามใจชอบ พอหยุดพิมพ์ราวครึ่งวินาที ระบบจะตรวจให้แล้ววาดภาพขวาใหม่ทันที ถ้ามีข้อผิดพลาด ภาพจะค้างอยู่ที่ข้อมูลชุดที่ถูกต้องครั้งล่าสุด และรายการข้อผิดพลาดจะบอกเลขบรรทัดให้กดกระโดดไปแก้ได้เลย

เริ่มต้นให้เป็น 3 อาคาร อาคารละ 3 ชั้น ชั้นละ 2 ห้อง แต่ละชั้นมีบันได 2 ตำแหน่งขนาบห้องไว้ และมีทางเชื่อมระหว่างอาคาร 2 จุด (อาคาร 1–2 ที่ชั้น 2 กับอาคาร 2–3 ที่ชั้น 3)

    3. buildings.json — ทะเบียนอาคาร
    

    
    ไฟล์นี้มีสองส่วน คือ meta ที่เป็นค่ากลางของทั้งผัง และ buildings ที่เป็นรายชื่ออาคาร
    

    
    
      
    
        
          
    ฟิลด์ใน metaชนิดความหมาย
    
            
        
          
    schoolข้อความชื่อผัง ใช้แสดงเฉย ๆ
    
          
    unitข้อความหน่วยของพิกัด ปกติคือ "meter"
    
          
    floorHeightตัวเลขความสูงจริงต่อชั้นเป็นเมตร ใช้คำนวณระยะทาง 3 มิติของ A*
    
          
    floorsอาร์เรย์ตัวเลขชั้นทั้งหมดที่มีในผัง
    
          
    extentอาร์เรย์ 4 ตัวกรอบของผัง [xน้อยสุด, yน้อยสุด, xมากสุด, yมากสุด]
    
            
      
    
    
    

    
    
      
    
        
          
    ฟิลด์ของอาคารแต่ละหลังจำเป็นความหมาย
    
            
        
          
    idต้องมีรหัสอาคาร ห้ามซ้ำ เช่น "b1" — ฟิลด์ building ของโหนดจะอ้างมาที่นี่
    
          
    nameต้องมีชื่อเต็ม เช่น "อาคาร 1"
    
          
    shortNameไม่บังคับชื่อย่อที่ใช้ในคำบอกทาง เช่น "อ.1"
    
          
    floorsควรมีชั้นที่อาคารนี้มี ใช้ตรวจว่าโหนดอยู่ชั้นที่มีจริงหรือเปล่า
    
          
    colorควรมีสีประจำอาคารแบบ #rrggbb
    
          
    rectไม่บังคับกรอบพื้นที่อาคาร [x1, y1, x2, y2]
    
          
    zone, code, axis, description, photoไม่บังคับข้อมูลประกอบ ไม่มีผลต่อการคำนวณ
    
            
      
    
    
    
  
    

  
  
    
    
    4. nodes.json — จุดทุกจุดในผัง
    

    
    โหนดหนึ่งตัวเขียนได้สั้น ๆ แบบนี้ (เขียนบรรทัดเดียวหรือหลายบรรทัดก็ได้ JSON ไม่สนใจการเว้นบรรทัด)
    

    
    
      {"id": "b1-f1-r01", "name": "ห้อง 1101", "type": "classroom", "building": "b1", "floor": 1, "x": 4.0, "y": 0.0}
    
    

    
    
      
    
        
    ฟิลด์จำเป็นชนิดความหมาย
    
        
          
    idต้องมีข้อความรหัสเฉพาะของโหนด ห้ามซ้ำทั้งไฟล์ เพราะ edges.json อ้างถึงด้วยค่านี้
    
          
    nameต้องมีข้อความชื่อที่คนอ่าน ใช้แสดงบนภาพและในช่องค้นหา
    
          
    typeต้องมีข้อความชนิดของจุด กำหนดสีและสัญลักษณ์บนภาพ (ดูตารางถัดไป)
    
          
    x, yต้องมีตัวเลขพิกัดบนผังเป็นเมตร มองจากด้านบน
    
          
    floorควรมีตัวเลขชั้นที่โหนดอยู่ ใช้คำนวณความสูงบนภาพ ถ้าไม่ใส่จะถูกวางไว้ชั้นล่างสุด
    
          
    buildingควรมีข้อความ / nullid ของอาคารใน buildings.json · ทางเชื่อมที่ไม่ได้อยู่ในอาคารไหนให้ใส่ null
    
          
    aliasesไม่บังคับอาร์เรย์ข้อความคำค้นเพิ่มเติม เช่นรหัสห้อง ["1101"]
    
          
    description, photo, sourceไม่บังคับข้อความข้อมูลประกอบที่แสดงตอนคลิกดูรายละเอียด
    
            
      
    
    
    

    
    ชนิดของโหนดที่ระบบรู้จัก
    
    
    
      ชนิดที่ใช้จริงในผังนี้มีสามอย่าง คือ classroom, stairs และ bridge
      ส่วนที่เหลือเตรียมไว้ให้ต่อยอด ถ้าใส่ชนิดนอกรายการนี้ระบบยังวาดให้ แต่จะเตือนและใช้สีเทากลาง ๆ
    
    
    
    
      
    
        
    ชนิดความหมายชนิดความหมาย
    
        
          
    classroomห้องเรียนtoiletห้องน้ำ
    
          
    stairsบันไดofficeห้องสำนักงาน
    
          
    bridgeทางเชื่อมระหว่างอาคารcorridorทางเดิน
    
          
    elevatorลิฟต์junctionทางแยก
    
          
    entranceทางเข้าอาคารgateประตูโรงเรียน
    
            
      
    
    
    

    
    
      ตั้ง id ให้เป็นระบบ จะแก้ง่ายกว่ามาก
      
    
        ผังนี้ใช้แบบแผน b<อาคาร>-f<ชั้น>-r<ห้อง> เช่น b2-f3-r01
        และ b<อาคาร>-f<ชั้น>-st<บันได> เช่น b2-f3-stA
        พอ id เดาได้ การเขียน edges.json ก็แทบไม่ต้องเปิดดู nodes.json เลย
      
    
    
    

    
    โหนดคนละชั้นอยู่พิกัดเดียวกันได้
    
    
    
      สังเกตในตัวอย่างว่า b1-f1-r01 กับ b1-f2-r01 มี x, y เท่ากันเป๊ะ
      ต่างกันแค่ floor ซึ่งถูกต้องแล้ว เพราะห้องชั้นบนก็อยู่ตรงกับห้องชั้นล่างจริง ๆ
      ระบบแยกมันออกจากกันด้วยแกนสูงที่คำนวณจาก floor เอง
    
    
  
    

  
  
    
    
    5. edges.json — เส้นที่ต่อระหว่างจุด
    

    
    
      {"from": "b1-f1-stA", "to": "b1-f1-r01", "distance": 4.0, "time": 3, "type": "corridor", "bidirectional": true}
    
    

    
    
      
    
        
    ฟิลด์จำเป็นชนิดความหมาย
    
        
          
    from, toต้องมีข้อความid ของโหนดต้นทางและปลายทาง ต้องมีอยู่จริงใน nodes.json
    
          
    distanceต้องมีตัวเลข > 0ระยะทางเดินจริงเป็นเมตร — เป็นน้ำหนักของโหมด "ระยะทางสั้นสุด"
    
          
    timeควรมีตัวเลข > 0เวลาเดินเป็นวินาที — น้ำหนักของโหมด "เวลาน้อยสุด" ถ้าไม่ใส่ ระบบจะประมาณจาก distance ÷ 1.3
    
          
    typeควรมีข้อความชนิดของทาง กำหนดสีเส้น และใช้กับตัวเลือก "เลี่ยงบันได"
    
          
    bidirectionalไม่บังคับtrue / falsetrue (ค่าเริ่มต้น) = เดินได้ทั้งไปและกลับ · false = เดินได้ทางเดียวจาก from ไป to
    
          
    closedไม่บังคับtrue / falseใส่ true เพื่อปิดทางนั้นชั่วคราวโดยไม่ต้องลบบรรทัดทิ้ง
    
            
      
    
    
    

    
    ชนิดของเส้นเชื่อม
    
    
    
      
    
        
    ชนิดใช้เมื่อไร
    
        
          
    corridorทางเดินธรรมดาในชั้นเดียวกัน
    
          
    stairs_up / stairs_downบันไดขึ้นและลง แยกกันคนละบรรทัดเพราะใช้เวลาไม่เท่ากัน
    
          
    bridgeทางเชื่อมระหว่างอาคาร
    
          
    elevatorลิฟต์
    
          
    outdoor, ramp, entrance, roomทางเดินนอกอาคาร ทางลาด ทางเข้า และทางเข้าห้อง
    
            
      
    
    
    

    
    
      ทำไมบันไดต้องเขียนสองบรรทัด
      
    
        เดินขึ้นบันไดเหนื่อยกว่าเดินลง เวลาจึงไม่เท่ากัน (ตัวอย่างใช้ขึ้น 20 วินาที ลง 15 วินาที)
        ถ้าเขียนบรรทัดเดียวแบบ bidirectional: true ทั้งสองทิศจะใช้เวลาเท่ากันซึ่งไม่ตรงความจริง
        จึงต้องเขียนเป็นสองบรรทัดแบบทางเดียว
      
    
      
    
        {"from": "b1-f1-stA", "to": "b1-f2-stA", "distance": 7.5, "time": 20, "type": "stairs_up", "bidirectional": false}
    
        {"from": "b1-f2-stA", "to": "b1-f1-stA", "distance": 7.5, "time": 15, "type": "stairs_down", "bidirectional": false}
      
    
    
    

    
    
      ทำไมทางเชื่อมระหว่างอาคารต้องมีโหนดตรงกลาง
      
    
        แทนที่จะลากเส้นเดียวยาว 26 เมตรจากอาคารหนึ่งไปอีกอาคาร ตัวอย่างสร้างโหนดชนิด
        bridge ไว้ตรงกลางแล้วต่อสองเส้นข้างละ 13 เมตร
        ทำให้สะพานเป็นจุดที่ค้นหาเจอ คลิกดูได้ และคำบอกทางพูดถึงมันได้ว่า "เดินข้ามทางเชื่อม"
      
    
    
    
  
    

  
  
    
    
    6. แบบฝึกหัด
    
    
    ลองทำในห้องทดลองด้านบนตามลำดับ แต่ละข้อจะเห็นผลบนภาพทันที
    

    
    
      
    ① เพิ่มห้องที่สามให้อาคาร 1 ชั้น 1
    
      
    
        ไปที่แท็บ nodes.json กดปุ่ม + ห้องเรียน จะได้ห้อง b1-f1-r03 โผล่มาบนภาพ
        แต่จะมีคำเตือนว่า "ไม่มีเส้นเชื่อมเลย" เพราะยังเดินไปไม่ถึง
        จากนั้นไปแท็บ edges.json กด + ทางเดิน เพื่อต่อจากบันได 1ข เข้าห้องใหม่ คำเตือนจะหายไป
      
    
    
    
    
    
      
    ② ทำให้อาคาร 3 มีแค่ 2 ชั้น
    
      
    
        ลบโหนดทุกตัวที่ id ขึ้นต้นด้วย b3-f3- ออกจาก nodes.json
        แล้วดูว่าระบบฟ้องอะไรบ้าง — จะพบว่าเส้นเชื่อมที่ยังอ้างถึงโหนดเหล่านั้นกลายเป็นข้อผิดพลาดทันที
        ต้องตามลบใน edges.json ให้ครบ รวมถึงทางเชื่อมอาคาร 2–3 ที่อยู่ชั้น 3 ด้วย
      
    
    
    
    
    
      
    ③ ย้ายทางเชื่อมอาคาร 1–2 ลงไปชั้น 1
    
      
    
        แก้ floor ของโหนด br-b1b2-f2 เป็น 1
        แล้วแก้ from/to ของเส้นเชื่อมสองเส้นให้ชี้ไปบันไดชั้น 1 แทน
        สังเกตว่าสะพานบนภาพย้ายลงมาอยู่ระนาบล่างสุด
      
    
    
    
    
    
      
    ④ ทำให้บันไดอาคาร 2 เดินขึ้นได้อย่างเดียว
    
      
    
        ลบบรรทัด stairs_down ของอาคาร 2 ทั้งหมด
        แล้วใช้แผงทดลองหาเส้นทางจากห้อง 2301 ไปห้อง 2101
        จะเห็นว่าระบบต้องอ้อมไปทางอาคารอื่น หรือหาเส้นทางไม่เจอเลย
      
    
    
    
    
    
      
    ⑤ ทำให้บันไดช้าจนคนเลือกเดินอ้อม
    
      
    
        เปลี่ยน time ของ stairs_up ทุกเส้นจาก 20 เป็น 200
        แล้วลองหาเส้นทางข้ามชั้นดู เส้นทางจะเปลี่ยนไปใช้ทางเชื่อมระหว่างอาคารแทน
        นี่คือหลักฐานว่าตัวเลขในไฟล์มีผลต่อคำตอบของอัลกอริทึมจริง ๆ
      
    
    
    
  
    

  
  
    
    
    7. ข้อผิดพลาดที่พบบ่อย
    

    
    
      
    
        
    อาการสาเหตุวิธีแก้
    
        
          
    
            ฟ้อง Unexpected token
            มีคอมมาเกินหลังรายการสุดท้าย หรือลืมคอมมาระหว่างรายการ
            JSON ห้ามมีคอมมาปิดท้ายอาร์เรย์ กดเลขบรรทัดในรายการข้อผิดพลาดเพื่อกระโดดไปดู
          
    
          
    
            ฟ้องว่า JSON ผิดรูปแบบทั้งที่ดูปกติ
            ใช้ ' แทน " หรือใส่คอมเมนต์ //
            JSON ใช้ได้แค่อัญประกาศคู่ และไม่รองรับคอมเมนต์เลย
          
    
          
    
            เส้นหายไปเงียบ ๆ
            from หรือ to พิมพ์ id ผิด
            ระบบจะฟ้องว่า "อ้างถึงโหนดที่ไม่มีอยู่" คัดลอก id จาก nodes.json มาวางแทนการพิมพ์เอง
          
    
          
    
            โหนดใหม่ลอยอยู่เฉย ๆ
            เพิ่มโหนดแล้วลืมเพิ่มเส้นเชื่อม
            ทุกโหนดต้องมีอย่างน้อยหนึ่งเส้น ไม่งั้นค้นเจอแต่เดินไปไม่ถึง
          
    
          
    
            เตือนว่า "เดินไปไม่ถึง" หลายโหนด
            กราฟขาดเป็นสองก้อน เช่นลบทางเชื่อมระหว่างอาคารออก
            เติมเส้นที่เชื่อมสองก้อนเข้าหากัน แล้วคำเตือนจะหายไป
          
    
          
    
            ชั้นบนกับชั้นล่างทับกันบนภาพ
            floor เป็นข้อความ "2" ไม่ใช่ตัวเลข 2
            ตัวเลขใน JSON ต้องเขียนโดยไม่มีอัญประกาศ
          
    
          
    
            เส้นทางที่ได้ดูแปลก ๆ
            distance ไม่สมจริง เช่นทางเดิน 4 เมตรใส่เป็น 0.4
            อัลกอริทึมเชื่อตัวเลขในไฟล์เสมอ ระยะทางผิดคำตอบก็ผิดตาม
          
    
          
    
            ขึ้นบันไดกับลงบันไดใช้เวลาเท่ากัน
            เขียนบันไดเป็นเส้นเดียวแบบ bidirectional: true
            แยกเป็นสองบรรทัดแบบทางเดียว ตามหัวข้อ 5
          
    
            
      
    
    
    
  
    

  
  
    
    
    8. เอาไปใช้จริง
    

    
    เมื่อข้อมูลในห้องทดลองผ่านการตรวจครบแล้ว เอาไปใช้กับหน้าแผนที่จริงได้สองทาง
    

    
    
      
    
        
    ทางที่ 1 — ดาวน์โหลดแล้ววางทับ
    
        
    
          กดปุ่มดาวน์โหลดทั้งสามไฟล์ แล้วนำไปวางทับในโฟลเดอร์ data/ ของโปรเจกต์
          จากนั้นตรวจซ้ำด้วยสคริปต์ฝั่งเครื่อง แล้วเปิด หน้าแผนที่ ได้เลย
        
    
        
    python tools/validate_data.py
    
      
    
      
    
        
    ทางที่ 2 — แก้ที่ตัวสร้างข้อมูล
    
        
    
          ถ้าผังมีแบบแผนซ้ำ ๆ (ทุกอาคารหน้าตาเหมือนกัน) การไล่พิมพ์ JSON ทีละบรรทัดจะช้ามาก
          ให้ไปแก้ตารางค่าคงที่ในไฟล์ tools/generate_data.py แทน — จำนวนอาคาร ชั้น ห้อง
          ตำแหน่งบันได และตารางทางเชื่อม อยู่ตรงหัวไฟล์ทั้งหมด แล้วสั่งสร้างใหม่
        
    
        
    python tools/generate_data.py
    
      
    
    
    

    
    
      ระวังจุดเดียว
      
    
        tools/generate_data.py จะเขียนทับไฟล์ใน data/ ทั้งหมด
        ถ้าแก้ JSON ด้วยมือไว้แล้วมารันสคริปต์ งานที่แก้จะหายไป
        เลือกอย่างใดอย่างหนึ่งให้ชัดว่าจะแก้ด้วยมือหรือแก้ที่สคริปต์
