# แผนที่นำทางภายในโรงเรียนบดินทรเดชา (สิงห์ สิงหเสนี)

เว็บไซต์แผนที่และระบบค้นหาเส้นทางภายในโรงเรียน จำลองพื้นที่โรงเรียนเป็น **กราฟถ่วงน้ำหนักแบบมีทิศทาง**
แล้วใช้อัลกอริทึม Dijkstra / A* หาเส้นทางที่สั้นหรือเร็วที่สุดจากจุดหนึ่งไปยังห้องเรียนหรือห้องต่าง ๆ

เป็นเว็บแบบ static ล้วน (HTML + CSS + JavaScript ไม่มี build step ไม่มี dependency)
วางบน GitHub Pages ได้ทันที

## ความสามารถ

| ความสามารถ | รายละเอียด |
|---|---|
| ค้นหาเส้นทาง | เลือกจุดเริ่มต้นและจุดหมาย ระบบคำนวณเส้นทางสั้นที่สุดพร้อมบอกทางทีละขั้น |
| ค้นหาได้หลายแบบ | พิมพ์รหัสห้อง (`5401`) ชื่อชั้นเรียน (`ม.1/3`) ชื่อห้อง หรือชื่อวิชาก็ได้ |
| เลือกเกณฑ์ | หา **ระยะทางสั้นสุด** หรือ **เวลาน้อยสุด** (บันไดขึ้นช้ากว่าลง จึงให้ผลต่างกันได้) |
| เลี่ยงบันได | ตัดเส้นเชื่อมชนิดบันไดออกจากกราฟ เหลือเฉพาะลิฟต์และทางลาด |
| สลับอัลกอริทึม | เทียบ A* กับ Dijkstra ได้ พร้อมแสดงจำนวนโหนดที่สำรวจและเวลาที่ใช้คำนวณ |
| หาจุดใกล้ที่สุด | ปุ่มหา ห้องน้ำ / บันได / ห้องพยาบาล / โรงอาหาร / ประตู / ห้องสมุด / ห้องคอม / สนามกีฬา ที่ใกล้ที่สุด |
| แผนที่แบบผังพื้น | วาดเป็นผังพื้นจริง เห็นกล่องห้อง ผนัง ช่องประตู ทางเดินกลาง บันได และลิฟต์ |
| แผนที่แบบโต้ตอบ | เลื่อน ซูม แตะเลือกห้อง สลับชั้น 1–5 กรองประเภทสถานที่จากแถบสัญลักษณ์ |
| รายละเอียดสถานที่ | ชื่อ อาคาร ชั้น ประเภท คำอธิบาย และรูปถ่าย |
| แชร์เส้นทาง | เส้นทางที่ค้นหาจะถูกเก็บใน URL คัดลอกส่งต่อแล้วเปิดได้เส้นทางเดิม |
| แก้ไขข้อมูลในเบราว์เซอร์ | หน้า `editor.html` เพิ่ม/ลบ/ย้ายโหนด เชื่อมเส้น ตรวจสอบข้อมูล และส่งออกเป็น JSON |
| รองรับมือถือ | แผงค้นหาเป็น bottom sheet ปัดขึ้น-ลงได้ รองรับการซูมแบบสองนิ้ว |
| โหมดมืด | ปรับตามการตั้งค่าของเครื่องอัตโนมัติ |

## เริ่มใช้งาน

**ต้องเปิดผ่านเว็บเซิร์ฟเวอร์** เพราะหน้าเว็บโหลดข้อมูลจากไฟล์ JSON ด้วย `fetch()`
ซึ่งเบราว์เซอร์จะบล็อกถ้าเปิดไฟล์ด้วย `file://` ตรง ๆ

```bash
python -m http.server 8000
```

แล้วเปิด <http://localhost:8000>

ถ้าใช้ Node.js:

```bash
npx serve .
```

## นำขึ้น GitHub Pages

### วิธีที่ 1 — ตั้งค่าผ่านหน้าเว็บ GitHub (ง่ายที่สุด)

```bash
git init
git add .
git commit -m "เพิ่มเว็บแผนที่นำทางภายในโรงเรียน"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ-repo>.git
git push -u origin main
```

จากนั้นที่หน้า repo บน GitHub ไปที่ **Settings → Pages** แล้วตั้งค่า

- **Source**: `Deploy from a branch`
- **Branch**: `main` และโฟลเดอร์ `/ (root)`

รอสักครู่เว็บจะขึ้นที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>/`

### วิธีที่ 2 — ใช้ GitHub Actions

โปรเจกต์นี้มีไฟล์ [`.github/workflows/pages.yml`](.github/workflows/pages.yml) มาให้แล้ว
ถ้าเลือกวิธีนี้ ให้ตั้ง **Settings → Pages → Source** เป็น `GitHub Actions`
ทุกครั้งที่ push ขึ้น `main` ระบบจะ deploy ให้อัตโนมัติ

> ไฟล์ `.nojekyll` ที่อยู่ในโปรเจกต์มีไว้บอก GitHub Pages ว่าไม่ต้องประมวลผลด้วย Jekyll
> อย่าลบออก

## ที่มาของข้อมูล

ข้อมูลในระบบมาจากสองแหล่ง และแยกความน่าเชื่อถือไว้ในฟิลด์ `source` ของทุกโหนด

### 1. ตารางเรียน ม.1 ภาคเรียนที่ 1/2569 — *ยืนยันแล้ว*

ถอดรหัสห้องจากตารางเรียนจริงของนักเรียนชั้น ม.1 ทั้ง 18 ห้อง ได้รหัสห้องที่ยืนยันแล้ว 35 รายการ
โหนดเหล่านี้จะมีป้าย **✓ ยืนยันจากตารางเรียน** ในหน้าเว็บ

**รูปแบบรหัสห้องของโรงเรียนคือ `[อาคาร][ชั้น][เลขห้อง 2 หลัก]`**

| รหัส | แปลว่า | ใช้ทำอะไร |
|---|---|---|
| `5401` | อาคาร 5 ชั้น 4 ห้อง 01 | ห้องเรียนประจำ ม.1/1 |
| `5301` | อาคาร 5 ชั้น 3 ห้อง 01 | ห้องเรียนประจำ ม.1/7 |
| `5203` | อาคาร 5 ชั้น 2 ห้อง 03 | ห้องเรียนประจำ ม.1/13 |
| `1401` `1301` `1207` | อาคาร 1 | ห้องเรียนโครงการ English Programme (ม.1/16-1/18) |
| `4203` `4302` `4303` `4404` | อาคาร 4 | ห้องเรียนวิทยาศาสตร์ (ว21181 / ว21191) |
| `4109` `4110` | อาคาร 4 ชั้น 1 | ห้องศิลปะ (ศ20101) |
| `3406` | อาคาร 3 ชั้น 4 | ห้องพระ 1 — วิชาพระพุทธศาสนา (ส21111) |
| `7207` | อาคาร 7 ชั้น 2 | ห้องปฏิบัติการงานอาชีพ (ง21101) |
| `7302` | อาคาร 7 ชั้น 3 | ห้องศิลปะ (ศ20101) |
| `COM1`–`COM7` | ห้องคอมพิวเตอร์ | วิชา ว21183 / ว21193 / ง21281 |

> ตารางเรียนยืนยันว่ามี **อาคาร 7** อยู่จริง ซึ่งไม่ปรากฏชื่อในภาพแผนผังสนามสอบ
> ตำแหน่งของอาคาร 7 บนแผนที่จึงเป็นการวางไว้ชั่วคราว ต้องแก้ให้ตรงกับของจริง

### 2. ภาพแผนผังสนามสอบแบบ isometric + ภาพถ่ายทางอากาศ — *ประมาณการ*

ใช้กำหนดว่ามีอาคารอะไรบ้างและอยู่ตำแหน่งไหนเมื่อเทียบกัน ได้แก่
อาคาร 1-5, อาคารบดินทรพิพัฒน์, อาคารเฉลิมพระเกียรติ, ห้องวิชาการ และประตู 2

### 3. ส่วนที่เติมให้ครบ — *ยังไม่ได้ตรวจสอบ*

ห้องที่เหลือ (ห้องน้ำ บันได ห้องพักครู ห้องสำนักงาน และห้องเรียนที่ไม่ปรากฏในตารางเรียน ม.1)
สร้างขึ้นตามรูปแบบทั่วไปเพื่อให้กราฟสมบูรณ์ โหนดเหล่านี้มีป้าย **⚠ ข้อมูลตัวอย่าง**
และควรแก้ให้ตรงกับของจริงก่อนนำไปใช้งานจริง

เนื่องจากแผนที่วาดเป็นผังพื้น ถ้าเว้นห้องว่างไว้จะเห็นเป็นช่องโหว่กลางอาคาร
ระบบจึงเติมห้องเรียนตามรหัสของอาคารนั้นให้เต็มทุกชั้น เช่น อาคาร 5 ชั้น 4
รู้จริงแค่ห้อง 5401-5406 ที่เหลือจะเติมเป็น 5407, 5408, … ไปจนเต็มความยาวอาคาร

## โครงสร้างข้อมูลกราฟ

ข้อมูลกราฟแยกเป็นไฟล์ JSON ต่างหาก แก้ไขด้วยมือหรือผ่านหน้า `editor.html` ก็ได้

### `data/nodes.json` — โหนด

```jsonc
{
  "version": "1.0",
  "nodes": [
    {
      "id": "b1-f1-r3",              // รหัสไม่ซ้ำกัน ใช้อ้างอิงในไฟล์ edges.json
      "name": "ห้องพยาบาล",           // ชื่อที่แสดงและใช้ค้นหา
      "type": "health_room",         // ประเภท (ดูตารางด้านล่าง)
      "building": "b1",              // รหัสอาคาร หรือ null ถ้าอยู่กลางแจ้ง
      "floor": 1,                    // ชั้น (กลางแจ้งใช้ 0)
      "x": 218.5,                    // พิกัดบนผัง หน่วยเมตร (x เพิ่มไปทางตะวันออก)
      "y": 179.5,                    // (y เพิ่มไปทางใต้)
      "description": "ปฐมพยาบาลเบื้องต้น",
      "photo": "assets/photos/nurse-room.jpg",   // เว้นว่างได้
      "aliases": ["ห้องพยาบาล", "nurse"],         // คำค้นเพิ่มเติม
      "source": "ข้อมูลตัวอย่าง (ยังไม่ได้ตรวจสอบ)", // ที่มาของข้อมูล ใช้แสดงป้ายในหน้าเว็บ

      // สองฟิลด์นี้ใช้วาดผังพื้น มีเฉพาะห้อง บันได และลิฟต์
      "rect": [212.5, 176.0, 223.5, 183.4],      // กรอบห้อง [x1, y1, x2, y2]
      "door": [218.0, 183.4]                     // ตำแหน่งประตูที่ติดทางเดิน
    }
  ]
}
```

**ประเภทโหนดที่รองรับ**

| `type` | ความหมาย | | `type` | ความหมาย |
|---|---|---|---|---|
| `classroom` | ห้องเรียน | | `stairs` | บันได |
| `lab` | ห้องปฏิบัติการ | | `elevator` | ลิฟต์ |
| `computer_lab` | ห้องคอมพิวเตอร์ | | `entrance` | ทางเข้าอาคาร |
| `teacher_room` | ห้องพักครู | | `gate` | ประตูโรงเรียน |
| `office` | ห้องสำนักงาน / ธุรการ | | `landmark` | จุดสังเกต เช่น เสาธง |
| `library` | ห้องสมุด | | `corridor` | จุดบนทางเดินในอาคาร |
| `toilet` | ห้องน้ำ | | `junction` | ทางแยกกลางแจ้ง |
| `health_room` | ห้องพยาบาล | | `meeting` | ห้องประชุม |
| `canteen` | โรงอาหาร | | `activity` | ห้องกิจกรรม |
| `shop` | ร้านค้า | | `sport` | สนามกีฬา / สระว่ายน้ำ |

> `corridor` และ `junction` เป็นโหนดโครงสร้างของกราฟ จะไม่ปรากฏในช่องค้นหา
> และจะแสดงบนแผนที่เฉพาะตอนเปิด "แสดงโครงสร้างกราฟ"

### `data/edges.json` — เส้นเชื่อม

```jsonc
{
  "version": "1.0",
  "edges": [
    {
      "from": "b1-f1-stairB",     // id ของโหนดต้นทาง
      "to": "b1-f2-stairB",       // id ของโหนดปลายทาง
      "distance": 14.96,          // ระยะทาง หน่วยเมตร (ต้องมากกว่า 0)
      "time": 36,                 // เวลาเดิน หน่วยวินาที
      "type": "stairs_up",        // ชนิดเส้นทาง
      "bidirectional": false,     // false = เดินได้ทางเดียว
      "note": "ขึ้นบันไดไปชั้น 2"   // ไม่บังคับ
    }
  ]
}
```

**ชนิดเส้นเชื่อมและความเร็วเดินที่ใช้ประมาณเวลา**

| `type` | ความหมาย | ความเร็ว (ม./วินาที) |
|---|---|---|
| `outdoor` | ทางเดินกลางแจ้ง | 1.40 |
| `corridor` | ทางเดินในอาคาร | 1.30 |
| `entrance` | ทางเข้า-ออกอาคาร | 1.20 |
| `room` | ทางเข้าห้องจากทางเดิน | 1.10 |
| `ramp` | ทางลาด | 0.90 |
| `stairs_down` | ลงบันได | 0.62 |
| `stairs_up` | ขึ้นบันได | 0.42 |
| `elevator` | ลิฟต์ (รวมเวลารอ) | — ใช้เวลาคงที่ |

> **บันไดเป็นเส้นเชื่อมแบบมีทิศทาง** ขึ้นกับลงใช้เวลาไม่เท่ากัน จึงต้องเขียนแยกเป็นสองรายการ
> โดยตั้ง `bidirectional: false` ทั้งคู่

## วิธีแก้ไขข้อมูล

### ทางที่ 1 — ใช้หน้า `editor.html` (แนะนำ)

1. เปิด <http://localhost:8000/editor.html>
2. เลือกโหมดที่ต้องการ
   - **เลือก / แก้ไข** — คลิกโหนดบนแผนที่เพื่อแก้ชื่อ ประเภท คำอธิบาย รูปถ่าย
   - **เพิ่มโหนด** — คลิกตำแหน่งบนแผนที่ ระบบเดาอาคารและชั้นจากจุดที่คลิกให้
   - **เชื่อมเส้น** — คลิกโหนดต้นทางแล้วคลิกโหนดปลายทาง ระยะทางและเวลาคำนวณให้อัตโนมัติ
3. กด **ตรวจสอบข้อมูล** เพื่อหา id ซ้ำ เส้นเชื่อมที่ชี้ไปโหนดที่ไม่มีอยู่ และโหนดที่เดินไปไม่ถึง
4. กด **ส่งออก JSON** แล้วนำไฟล์ที่ได้ไปวางทับใน `data/`
5. `git commit` แล้ว `git push`

> การแก้ไขจะถูกเก็บชั่วคราวใน localStorage ของเบราว์เซอร์เพื่อกันข้อมูลหาย
> แต่ **ไม่ได้เขียนทับไฟล์ในโปรเจกต์ให้** ต้องส่งออกแล้วนำไปวางเองเสมอ

### ทางที่ 2 — แก้ไฟล์ JSON ตรง ๆ

แก้ `data/nodes.json` และ `data/edges.json` ด้วย editor ที่ถนัด แล้วตรวจสอบด้วย

```bash
python tools/validate_data.py
```

สคริปต์จะตรวจ id ซ้ำ · เส้นเชื่อมที่อ้างถึงโหนดที่ไม่มีอยู่ · ค่าระยะทาง/เวลาที่ไม่ถูกต้อง ·
โหนดที่ไม่มีเส้นเชื่อม · และความเชื่อมต่อของกราฟทั้งหมดด้วย BFS

### เพิ่มรูปถ่ายให้สถานที่

1. วางไฟล์รูปไว้ใน `assets/photos/`
2. ใส่ path ลงในฟิลด์ `photo` ของโหนดนั้น เช่น `"photo": "assets/photos/room-121.jpg"`

### สร้างข้อมูลใหม่ทั้งหมด

> ควรใช้เฉพาะตอนต้องการเริ่มใหม่ หลังจากนั้นให้ถือว่าไฟล์ JSON เป็นต้นฉบับ

## ทฤษฎีกราฟที่ใช้

พื้นที่โรงเรียนถูกจำลองเป็นกราฟ `G = (V, E)` โดย

- **V (โหนด)** = สถานที่ เช่น ห้องเรียน บันได ห้องน้ำ ห้องพักครู ห้องธุรการ ประตู และจุดแยกบนทางเดิน
- **E (เส้นเชื่อม)** = ทางเดินระหว่างสองสถานที่ ถ่วงน้ำหนักด้วยระยะทาง (เมตร) และเวลาเดิน (วินาที)

| อัลกอริทึม | ใช้ทำอะไร | ความซับซ้อน |
|---|---|---|
| **Dijkstra** | หาเส้นทางน้ำหนักรวมต่ำสุด ใช้ binary min-heap เป็นคิวลำดับความสำคัญ | O((V + E) log V) |
| **A\* search** | Dijkstra + ค่าประมาณระยะที่เหลือ (ระยะยุคลิด 3 มิติ) สำรวจโหนดน้อยกว่ามาก | O((V + E) log V) แต่เร็วกว่าในทางปฏิบัติ |
| **Multi-target Dijkstra** | หา "ห้องน้ำที่ใกล้ที่สุด" โดยเดินกราฟรอบเดียว ไม่ต้องคำนวณทีละเป้าหมาย | O((V + E) log V) |
| **BFS** | ตรวจว่ากราฟยังเชื่อมต่อกันครบทุกโหนด | O(V + E) |

**ทำไม A\* ยังได้คำตอบที่ถูกต้อง** — ฟังก์ชันประมาณค่าใช้ระยะเส้นตรงแบบ 3 มิติ
(รวมความต่างของชั้นคูณความสูงต่อชั้น) ซึ่งไม่มีทางมากกว่าระยะทางเดินจริง
จึงเป็น *admissible heuristic* และรับประกันว่าได้เส้นทางสั้นที่สุดเช่นเดียวกับ Dijkstra

ลองเปรียบเทียบเองได้จากช่อง "อัลกอริทึม" ในหน้าเว็บ — ระบบจะแสดงจำนวนโหนดที่สำรวจของแต่ละแบบ

## ข้อจำกัดของข้อมูลชุดนี้

โปรดอ่านก่อนนำไปใช้งานจริง

1. **ผังเป็นแบบจำลอง ไม่ใช่แบบแปลนจริง** — ตำแหน่งและขนาดอาคารประมาณจากภาพแผนผังสนามสอบ
   แบบ isometric และภาพถ่ายทางอากาศ จึงถูกต้องในเชิงตำแหน่งสัมพัทธ์เท่านั้น
2. **ตำแหน่งห้องภายในชั้นเป็นการจัดเรียงอัตโนมัติ** — ระบบแบ่งความยาวอาคารเป็นช่องเท่า ๆ กัน
   แล้ววางห้องสลับสองฝั่งทางเดิน **ลำดับและด้านของห้องจึงยังไม่ตรงกับของจริง**
   แม้ว่ารหัสห้องจะถูกต้องก็ตาม
3. **มีเฉพาะรหัสห้องที่ยืนยันแล้ว 35 รายการ** — ที่เหลือเป็นข้อมูลตัวอย่างที่เติมให้ครบ
   ดูป้ายกำกับในแผงรายละเอียดของแต่ละสถานที่ว่าเป็นข้อมูลแบบไหน
   (รายละเอียดที่หัวข้อ [ที่มาของข้อมูล](#ที่มาของข้อมูล))
4. **ระยะทางและเวลาเป็นค่าประมาณ** — คำนวณจากพิกัดบนผังจำลองและความเร็วเดินเฉลี่ย
   ไม่ได้วัดจากสถานที่จริง
5. **ข้อมูลลิฟต์และทางลาดยังไม่ครบ** — ขณะนี้มีลิฟต์บันทึกไว้เฉพาะอาคารเฉลิมพระเกียรติ
   ฟังก์ชัน "เลี่ยงบันได" จึงยังหาเส้นทางขึ้นชั้นบนของอาคารอื่นไม่ได้
   **หากจะใช้เพื่อการเข้าถึงสำหรับผู้ใช้รถเข็นหรือผู้ที่เดินไม่สะดวก ต้องสำรวจและกรอกข้อมูลจริงก่อน**

6. **ตำแหน่งของอาคาร 7 และห้อง COM1-COM7 ยังไม่ยืนยัน** — ตารางเรียนบอกว่ามีอยู่จริง
   แต่ไม่ได้บอกว่าอยู่ตรงไหน จึงวางไว้ในตำแหน่งที่สมเหตุสมผลไปก่อน
7. **ยังไม่มีข้อมูลของอาคาร 6** — ไม่พบทั้งในภาพแผนผังและในตารางเรียน ม.1

ทั้งหมดนี้แก้ไขได้ผ่าน `editor.html` หรือแก้ไฟล์ JSON โดยตรง
