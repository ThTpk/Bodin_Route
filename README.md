# กราฟเส้นทางภายในอาคาร — มุมมอง 3 มิติ

เว็บแสดง **โหนด (node)** และ **เส้นเชื่อม (edge)** ของอาคารใน
**โรงเรียนบดินทรเดชา (สิงห์ สิงหเสนี)** เป็นภาพ 3 มิติที่หมุน เลื่อน และซูมได้
พร้อมค้นหาเส้นทางที่สั้น/เร็วที่สุดด้วย Dijkstra และ A*

ผังอาคารและทางเชื่อมถอดมาจากผัง 3 มิติของโรงเรียนที่
<https://thtpk.github.io/3D_Map/> (ไฟล์ `buildings.js`)

ไม่มีแผนที่ ไม่มีผังพื้น ไม่มีภาพพื้นหลัง — ทุกอย่างที่เห็นบนจอมาจาก
`data/nodes.json` และ `data/edges.json` เท่านั้น

เป็นเว็บ static ล้วน (HTML + CSS + JavaScript ไม่มี build step ไม่มี dependency ภายนอก)
การวาดภาพ 3 มิติเขียนเองบน `<canvas>` 2D ไม่ได้ใช้ WebGL หรือไลบรารีใด ๆ

## โครงสร้างข้อมูลที่จำลอง

ผังทั้งหมดถอดจากผัง 3 มิติของโรงเรียน โดยคิดอาคารแต่ละหลังเป็น **แนวทางเดินกลางอาคาร**
(เส้นตรงจากจุดกึ่งกลางผนังหัวอาคารถึงจุดกึ่งกลางผนังท้ายอาคาร)
แล้วแปลงพิกัดภูมิศาสตร์เป็นพิกัดเมตรในระนาบ

```
x = ทิศตะวันออก (เมตร)      y = ทิศเหนือ (เมตร)
จุดกำเนิด (0, 0) = lon 100.61525 , lat 13.76730
```

### บันได

**บันไดอยู่ด้านข้างอาคาร** คือหัวและท้ายของแนวทางเดินทุกหลัง (ตำแหน่ง `t = 0.0` และ `t = 1.0`)
แต่ละชั้นมีโหนดบันไดของตัวเอง (เช่น `b1-f1-stA`, `b1-f2-stA`)
แล้วเชื่อมชั้นต่อชั้นด้วยเส้นเชื่อมชนิดบันได จึงเป็นทางเดียวที่ข้ามชั้นภายในอาคารได้
ขึ้นกับลงใช้เวลาไม่เท่ากัน (19 กับ 14 วินาทีต่อช่วงชั้น) จึงเก็บเป็นเส้นเชื่อมแบบมีทิศทาง

ถ้าอาคารไหนมีบันไดกลางอาคารเพิ่ม ใส่คีย์ `stairs` ของอาคารนั้นเป็นรายการตำแหน่งได้เลย
เช่น `"stairs": (0.0, 0.5, 1.0)`

### ทางแยกระหว่างอาคาร

จุดที่แนวทางเดินสองอาคารบรรจบกันเป็นโหนดชนิด `junction` **หนึ่งตัวต่อหนึ่งคู่หนึ่งชั้น**
ใช้ร่วมกันทั้งสองแนว (เช่น `jn-b1-link-f2`) คู่ที่เชื่อมกันมี 12 คู่

```
ตึก 1 × อาคารเชื่อม   ตึก 2 × อาคารเชื่อม   ตึก 3 × อาคารเชื่อม   ตึก 4 × อาคารเชื่อม
ตึก 1 × ตึก 5         ตึก 2 × ตึก 5         ตึก 3 × ตึก 5
ตึก 1 × ทางเดินเชื่อม 1-2    ตึก 2 × ทางเดินเชื่อม 1-2
ตึก 2 × ทางเดินเชื่อม 2-3    ตึก 3 × ทางเดินเชื่อม 2-3
ตึก 1 × ทางเดินซุ้มโค้ง
```

วงรอบ (cycle) ที่เกิดจากตึก 1–3 + อาคารเชื่อม + ตึก 5 ทำให้มีเส้นทางให้เลือกมากกว่าหนึ่งทางจริง ๆ
ไม่ใช่โครงสร้างแบบต้นไม้ที่มีทางเดียวเสมอ

### ทางเดินกลางแจ้ง

ลานหน้าอาคาร 17 จุดที่ระดับชั้น 1 (ชนิด `plaza`) เชื่อมกลุ่มตึก 1–5
เข้ากับหอประชุม สนามกีฬา เรือนไทย อาคารกีฬา สระว่ายน้ำ และตึก 7

## ความสามารถ

- **ภาพกราฟ 3 มิติที่หมุน เลื่อน และซูมได้**
  - เมาส์: ลากเพื่อหมุน (yaw/pitch), Shift+ลาก หรือคลิกขวาลาก เพื่อเลื่อนจุดศูนย์กลาง, สกรอลล์เพื่อซูม
  - มือถือ: นิ้วเดียวหมุน สองนิ้วหุบ/กางเพื่อซูม
  - แผงปุ่มบนภาพ (ตาราง 3×3): กลางสี่ด้าน = เลื่อนจุดศูนย์กลาง บน/ล่าง/ซ้าย/ขวา,
    สี่มุม = หมุนซ้าย-ขวาและก้ม-เงย, ตรงกลาง = กลับไปกึ่งกลางกราฟ
    พร้อมปุ่ม ＋ － ⤢ สำหรับซูม และปุ่ม 🧭 สำหรับหันมุมมองให้เห็นเส้นทางทั้งเส้น
  - คีย์บอร์ด: ลูกศร = เลื่อน, Shift+ลูกศร = หมุน/เอียง, `+` `-` = ซูม, `F` = พอดีจอ,
    `C` = กึ่งกลาง, `R` = เห็นทั้งเส้นทาง
- **ปรับระยะห่างระหว่างชั้น** ด้วยแถบเลื่อน เพื่อให้แยกชั้นด้วยตาได้ง่ายขึ้น
- **เน้นทีละชั้น** — เลือกชั้นแล้วชั้นอื่นจะจางลง (ไม่ได้ซ่อน) จึงยังเห็นบริบททั้งกราฟ
- **หมุนอัตโนมัติ**, เปิด/ปิดระนาบอ้างอิงของชั้น, เปิด/ปิดป้ายชื่อ
- **ค้นหาเส้นทาง** ด้วย Dijkstra หรือ A* เลือกเกณฑ์ระยะทางหรือเวลา และเลี่ยงบันไดได้
- **ปุ่ม "ล้างค่า"** ล้างจุดเริ่มต้น จุดหมาย และเส้นทางที่แสดงอยู่ในคราวเดียว
  แล้วคืนมุมกล้องเริ่มต้นให้ด้วย
- **จุดวิ่งบอกทิศทางเดิน** — เมื่อได้เส้นทางแล้วจะมีจุดเรืองแสงพร้อมหางวิ่งจากต้นทางไปปลายทาง
  ซ้ำเป็นรอบ และมีลูกศรสีขาวกลางแต่ละช่วงบอกทิศแม้ภาพจะหยุดนิ่ง
- **จัดมุมมองให้เห็นเส้นทางทั้งเส้นอัตโนมัติ** เมื่อคู่ต้นทาง–ปลายทางเปลี่ยน
  โดยหมุนให้ต้นทางอยู่ซ้ายและปลายทางอยู่ขวา เส้นทางในชั้นเดียวจะมองเกือบจากด้านบน
  ส่วนเส้นทางข้ามชั้นจะเอียงไว้ให้เห็นการขึ้น-ลงชั้น
- **คำแนะนำการเดินทีละขั้น** พร้อมบอกจุดขึ้น-ลงบันไดและจุดข้ามทางเชื่อมระหว่างอาคาร
- **หาโหนดที่ใกล้ที่สุด** (บันได / ทางเชื่อม / ห้องเรียน) ด้วย multi-target Dijkstra
- **กรองตามประเภทโหนด** จากแถบสัญลักษณ์
- **แชร์เส้นทางผ่าน URL** เช่น `#from=b1-f1-r01&to=b7-f5-r10&by=time`

```bash
npx serve .
```

## นำขึ้น GitHub Pages

### วิธีที่ 1 — ตั้งค่าผ่านหน้าเว็บ GitHub (ง่ายที่สุด)

```bash
git push -u origin main
```

จากนั้นที่หน้า repo บน GitHub ไปที่ **Settings → Pages** แล้วตั้งค่า

- **Source**: `Deploy from a branch`
- **Branch**: `main` และโฟลเดอร์ `/ (root)`

รอสักครู่เว็บจะขึ้นที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>/`

### วิธีที่ 2 — ใช้ GitHub Actions

โปรเจกต์นี้มีไฟล์ [`.github/workflows/pages.yml`](.github/workflows/pages.yml) มาให้แล้ว
ถ้าเลือกวิธีนี้ ให้ตั้ง **Settings → Pages → Source** เป็น `GitHub Actions`
ทุกครั้งที่ push ขึ้น `main` ระบบจะ deploy ให้อัตโนมัติ

> ไฟล์ `.nojekyll` มีไว้บอก GitHub Pages ว่าไม่ต้องประมวลผลด้วย Jekyll อย่าลบออก

## วิธีแก้ไขข้อมูล

### ทางที่ 1 — แก้ที่ตัวสร้างข้อมูล (แนะนำ)

แก้ตารางค่าคงที่ด้านบนของ [`tools/generate_data.py`](tools/generate_data.py) แล้วรันใหม่

| ตัวแปร | ใช้กำหนด |
|---|---|
| `WINGS` | อาคารและทางเดินเชื่อมทุกหลัง — แนวทางเดิน (`line` เป็น lon/lat), จำนวนชั้น (`floors`), **จำนวนห้องต่อชั้น (`rooms`)**, ตำแหน่งบันได (`stairs`), ช่วงที่ชั้นล่างเปิดโล่ง (`voids`), ห้องพิเศษ (`extras`) |
| `JUNCTIONS` | คู่อาคารที่แนวทางเดินบรรจบกัน สคริปต์หาจุดตัดและชั้นที่ใช้ร่วมกันเอง |
| `PLACES` | สถานที่ที่เป็นโหนดเดียว เช่น หอประชุม สนามกีฬา สระว่ายน้ำ |
| `PLAZAS`, `OUTDOOR`, `ENTRANCES` | ลานกลางแจ้ง เส้นทางเดินกลางแจ้ง และทางเข้าอาคาร |
| `LON0`, `LAT0` | จุดกำเนิดของพิกัดเมตร |
| `STAIR_TIME_UP/DOWN`, `WALK_SPEED`, `OUTDOOR_SPEED` | เวลาเดินและเวลาขึ้น-ลงบันได |

**ปรับจำนวนห้อง** แก้คีย์ `rooms` ของอาคารนั้น ใส่เป็นตัวเลขเดียว (ทุกชั้นเท่ากัน)
หรือเป็น `{ชั้น: จำนวน}` แล้วรันสคริปต์ใหม่ สคริปต์จะกระจายห้องตามแนวทางเดินให้เอง
โดยเว้นช่วงที่ระบุไว้ใน `voids`

**เพิ่มอาคาร** เพิ่มรายการใน `WINGS` (ต้องมี `line` เป็นพิกัด lon/lat ของหัวและท้ายอาคาร)
แล้วเพิ่มคู่ทางแยกใน `JUNCTIONS` สคริปต์คำนวณพิกัด จุดตัด ระยะทาง และเวลาให้เองทั้งหมด

```bash
python tools/generate_data.py
```

ไฟล์ทั้งสามใน `data/` จะถูกเขียนทับใหม่ทั้งหมด

### ทางที่ 2 — แก้ไฟล์ JSON ตรง ๆ

แก้แล้วตรวจด้วย

```bash
python tools/validate_data.py
```

สคริปต์จะตรวจ id ซ้ำ, edge ที่อ้างถึงโหนดที่ไม่มีอยู่, ค่า `distance`/`time` ที่ไม่ถูกต้อง,
โหนดที่ไม่มีเส้นเชื่อม และตรวจด้วย BFS ว่ากราฟยังเชื่อมต่อกันครบทุกโหนด

### ทางที่ 3 — แก้บนหน้าเว็บที่ [`data-editor.html`](data-editor.html)

หน้านี้อธิบายทุกฟิลด์ของทั้งสามไฟล์ แล้วเปิดช่องให้แก้ JSON บนหน้าเว็บโดยตรง
ตรวจความถูกต้องด้วยกติกาชุดเดียวกับ `validate_data.py` (บอกเลขบรรทัดที่ผิดและกดกระโดดไปแก้ได้)
แล้ววาดโหนดกับเส้นเชื่อมที่ได้เป็นภาพ 3 มิติทันทีด้วย `js/view3d.js` ตัวเดียวกับหน้าแผนที่จริง

- เริ่มด้วยผังตัวอย่างขนาดเล็ก — 3 อาคาร อาคารละ 3 ชั้น ชั้นละ 2 ห้อง พร้อมทางเชื่อมระหว่างอาคาร
- กดปุ่มเดียวเพื่อดึงข้อมูลจริงของโรงเรียนเข้ามาดู หรือดาวน์โหลดไฟล์ที่แก้แล้วไปวางทับใน `data/`
- มีแผงทดลองหาเส้นทาง เพื่อพิสูจน์ว่าผังที่เขียนเดินถึงกันได้จริง

## การฉายภาพ 3 มิติ

`js/view3d.js` ทำงานสี่ขั้นตอนต่อหนึ่งเฟรม

1. **แกนตั้ง** — `z = (floor - ชั้นต่ำสุด) × ระยะห่างระหว่างชั้น`
   ค่าระยะห่างนี้ปรับได้จากแถบเลื่อนเพื่อให้เห็นชั้นชัดขึ้น และ**ไม่มีผลต่อการคำนวณเส้นทาง**
2. **หมุน** รอบแกนตั้งด้วยมุม `yaw` แล้ว**เอียง**ด้วยมุม `pitch`
3. **ฉายแบบเปอร์สเปกทีฟ** — `scale = focal / (dist + depth)`
   จุดที่ไกลกว่าจึงเล็กลงและโหนดที่อยู่ใกล้กล้องจะวาดใหญ่ขึ้น
4. **เรียงลำดับวาดจากไกลไปใกล้** (painter's algorithm) เพื่อให้การบังกันถูกต้อง
   ส่วนเส้นทางที่ค้นหาจะถูกวาดไว้บนสุดเสมอ

ปุ่ม "พอดีหน้าจอ" คำนวณระยะกล้องแบบปิด (closed form) จากโหนดทุกตัว
โดยแก้สมการ `|x| × focal / (dist + depth) = ครึ่งความกว้างจอ` แล้วเลือกค่าที่มากที่สุด

ปุ่ม "เห็นทั้งเส้นทาง" (🧭 / `R`) ใช้สมการเดียวกันแต่คิดจากเฉพาะจุดบนเส้นทาง
และเลือกมุม `yaw = atan2(-Δy, Δx)` ของเวกเตอร์ต้นทาง→ปลายทาง ซึ่งทำให้พจน์ `y1` เป็นศูนย์
แนวเส้นทางจึงนอนขวางจอเต็มความกว้าง โดยต้นทางอยู่ซ้ายและปลายทางอยู่ขวาเสมอ

## ทฤษฎีกราฟที่ใช้

| อัลกอริทึม | ใช้ทำอะไร | ความซับซ้อน |
|---|---|---|
| **Dijkstra** | เส้นทางน้ำหนักรวมต่ำสุด ใช้ binary min-heap | O((V + E) log V) |
| **A\*** | Dijkstra + heuristic ระยะยุคลิด 3 มิติ (admissible) | เท่ากันแต่สำรวจน้อยกว่า |
| **Multi-target Dijkstra** | หาโหนดประเภทที่ต้องการที่ใกล้ที่สุด เดินกราฟรอบเดียว | O((V + E) log V) |
| **BFS** | ตรวจความเชื่อมต่อของกราฟ (`tools/validate_data.py`) | O(V + E) |

heuristic ของ A* ใช้ระยะเส้นตรง 3 มิติซึ่งไม่มีทางเกินระยะจริง จึงยังได้เส้นทางสั้นที่สุด
เหมือน Dijkstra ทุกประการ

## ข้อจำกัด

- **ตำแหน่งและรูปร่างอาคารอ้างอิงของจริง** (ถอดจากผัง 3 มิติซึ่งอิง OpenStreetMap และภาพดาวเทียม)
  แต่ **ผังห้องภายในยังเป็นค่าตั้งต้น** จำนวนห้องต่อชั้นประมาณจากความยาวอาคาร ไม่ใช่ผังห้องจริง
  ระยะทางและเวลาที่แสดงจึงเป็นค่าประมาณ
- ห้องแต่ละห้องแทนด้วยโหนดเดียวที่อยู่บนแนวทางเดิน (คิดเสมือนตำแหน่งประตูห้อง)
  และอาคารแต่ละหลังมีทางเดินเส้นเดียว ยังไม่ได้แยกทางเดินฝั่งหน้า-ฝั่งหลัง
- ลานและทางเดินกลางแจ้งเป็นตำแหน่งประมาณจากภาพดาวเทียม ยังไม่ได้วัดจากของจริง
- ในชุดข้อมูลนี้ **บันไดเป็นทางเดียวที่ข้ามชั้นได้** ยังไม่มีลิฟต์หรือทางลาด
  ถ้าเปิดตัวเลือก "เลี่ยงบันได" แล้วปลายทางอยู่คนละชั้น จะหาเส้นทางไม่พบ
- ทางเดินเชื่อมฝั่งตะวันตกมีเฉพาะชั้น 3–4 การข้ามอาคารที่ชั้น 1–2 จึงต้องผ่านอาคารเชื่อม
  ตึก 5 หรือเดินลงไปที่ทางเดินกลางแจ้ง
- ตึก 7, สระว่ายน้ำ, เรือนไทย และสนามกีฬา เชื่อมกับกลุ่มอาคารเรียนทางทางเดินกลางแจ้งเท่านั้น
